## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
## Problem

Aktuell embedded der Build nur `favicon.png` ins Binary. `dist/index.html`, `dist/web/main.js`, `dist/web/main.css` werden zur Laufzeit via `resolveHtml()`/`resolveAsset()` gesucht — zuerst im Binary-Verzeichnis, dann in `cwd/dist/`, dann in `cwd/src/web/`. Nach `bun i -g .` und Ausführung des Binary aus einem anderen Verzeichnis findet der Server kein `dist/` → Frontend bleibt weiss.

## Lösung

Nach dem Build-Schritt in `scripts/build.ts` alle `dist/`-Dateien via `import ... with { type: "file" }` in eine generierte `src/server/embedded-assets.ts` schreiben. `resolveHtml()` und `resolveAsset()` nutzen embedded refs statt Filesystem-Suche. Filesystem-Fallback bleibt für `bun run dev`.

- NEU: scripts/generate-embedded-assets.ts

## Implementation Notes

## Implementation Steps

1. Create `scripts/generate-embedded-assets.ts`:
   - Scan `dist/` rekursiv nach Dateien (aktuell: index.html, web/main.js, web/main.css)
   - Generiere `src/server/embedded-assets.ts` mit for each file: `export { default as name } from "../../dist/path" with { type: "file" }`

2. Modify `scripts/build.ts`:
   - After line 69 (bundled html written): `await generateEmbeddedAssets()`
   - Import generateEmbeddedAssets from the new script

3. Modify `src/server/index.ts`:
   - `resolveHtml()`: If import.meta.dirname hat kein src/ → embedded ref, else filesystem (dev)
   - `resolveAsset(path)`: Lookup in embedded map, fallback filesystem
   - Embedded map: `{ "/web/main.js": mainJs, "/web/main.css": mainCss, "/index.html": indexHtml }`

4. Add `.gitignore` entry: `src/server/embedded-assets.ts`

## Edge Cases
- `bun run dev`: import.meta.dirname enthaelt src/ → filesystem fallback (korrekt)
- After build + binary: import.meta.dirname ist binary dir → embedded refs (korrekt)
- If embedded-assets.ts nicht existiert (frischer clone, kein build) → dynamic import() mit try/catch
