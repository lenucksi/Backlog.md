## Description

## Problem

The compiled binary does NOT embed frontend assets. At runtime, resolveHtml() and resolveAsset() search:
Binary dir -> cwd/dist/ -> cwd/src/web/

The npm files field does NOT include dist/. So npm-published binaries cannot serve the frontend without manual setup. The binary is not standalone.

Currently only favicon.png is embedded (with { type: "file" }).

### Goal
After vite build, embed all dist/ assets into the binary.

## Location
- scripts/build.ts (post-vite-build step)
- src/server/index.ts (resolveHtml/resolveAsset)
- Generated: src/server/embedded-assets.ts

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. After vite build, list all files in dist/
2. Generate src/server/embedded-assets.ts with file imports:
   import html from "../../dist/index.html" with { type: "file" };
3. In server code, import embedded-assets instead of runtime resolution
4. Simplify resolveHtml/resolveAsset to use embedded refs
5. Keep filesystem fallback for development mode
<!-- SECTION:PLAN:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Generated file must be gitignored. Each embedded file becomes a path relative to binary at runtime. If 50+ chunks, generating individual imports may be unwieldy - consider a manifest approach. Check Bun 1.3.x docs for current embedded asset patterns.
