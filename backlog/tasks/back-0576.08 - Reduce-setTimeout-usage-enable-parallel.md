## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Zwei Tasks in einem Ticket, weil sie zusammenhängen:
1. setTimeout/Sleep-Aufrufe in Tests reduzieren/eliminieren (54 calls in 17 Dateien)
2. `--parallel` in package.json aktivieren und flaky Tests fixen

## Phase 1: setTimeout Reduction

### Problem
54 setTimeout/sleep calls in 17 Dateien, ca. 2-3s reine Wartezeit. Viele sind polling-workarounds die durch `retry()` aus `test-utils.ts` ersetzt werden können.

### Files mit setTimeout/sleep
```bash
grep -rn 'setTimeout\|sleep(' --include='*.test.ts' src/test/ | grep -v 'function sleep\|sleep('
```

### Replace-Patterns:

#### Polling 100ms → retry():
```typescript
// VORHER:
await new Promise((r) => setTimeout(r, 100));
expect(something).toBeTruthy();

// NACHHER:
import { retry } from "./test-utils.ts";
await retry(() => expect(something).toBeTruthy(), 5);
```

#### Micro-waits (5-10ms) → komplett entfernen:
```typescript
// VORHER (in zz-ui-components-coverage.test.ts):
await new Promise((r) => setTimeout(r, 10));

// NACHHER: einfach löschen, war nur ein "warte mal kurz"
```

#### Editor-handoff waits → event-basiert:
```typescript
// VORHER (200-2000ms):
setTimeout(() => process.exit(0), 200);
await new Promise((r) => setTimeout(r, 2000));

// NACHHER: Event-basiert warten oder Timeout reduzieren
```

#### Timeout-Variablen → bestehen lassen (sind Grenzwerte, keine Verzögerungen):
```typescript
// Diese sind OK:
const timer = setTimeout(() => reject(new Error("timeout")), 5000);
```

### Spezifische Files:
- `src/test/zz-board-coverage.test.ts` — 11× 100ms → retry()
- `src/test/zz-ui-components-coverage.test.ts` — 7× 5-10ms → löschen
- `src/test/tui-interactive-editor-handoff.test.ts` — 6× 200-2000ms → reduzieren/event
- `src/test/status-callback.test.ts` — 4× 100-200ms → retry()
- `src/test/content-store-comprehensive.test.ts` — 4× 200ms → retry()
- `src/test/zz-task-viewer-coverage.test.ts` — 3× 100ms → retry()
- `src/test/tui-termless-core.test.ts` — 3× 200-500ms → reduzieren/event
- Rest: ähnlich behandeln

## Phase 2: --parallel aktivieren

### Schritte:
1. `package.json` ändern — `--parallel` Flag hinzufügen:
```json
"test": "bun test --parallel --timeout=30000 --path-ignore-patterns='worktrees/*' --path-ignore-patterns='src/test/e2e/*'"
```

2. NO-PARALLEL Files ausschließen (files mit `process.chdir()` oder TUI):
```json
--path-ignore-patterns='src/test/runtime-cwd.test.ts'
--path-ignore-patterns='src/test/tui-interactive-editor-handoff.test.ts'
```

3. Bot-CI test script anpassen (falls vorhanden)

4. Vollständigen Testlauf starten:
```bash
bun test --parallel --timeout=30000 --path-ignore-patterns='worktrees/*' --path-ignore-patterns='src/test/e2e/*'
```

5. Flaky Tests identifizieren und fixen:
   - Globale State-Leaks (console.log/exit mocks) → restore in afterEach
   - File-IO Races → unique dirs + retry
   - Port-Konflikte → unique ports
