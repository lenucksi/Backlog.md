## Migration Patterns

### Pattern A: task create mit AC
```typescript
// VORHER ($ subprocess ~200ms):
const result = await $`bun ${CLI_PATH} task create "Test Task" --ac "Criterion"`.cwd(TEST_DIR).quiet();
expect(result.exitCode).toBe(0);

// NACHHER (Core API ~2ms):
const core = new Core(TEST_DIR);
await core.createTaskFromInput({ title: "Test Task", acceptanceCriteria: [{ text: "Criterion", checked: false }] });
// No exitCode check needed — Core throws on error
```

### Pattern B: task edit AC hinzufügen
```typescript
const core = new Core(TEST_DIR);
await core.updateTaskFromInput("task-1", { addAcceptanceCriteria: ["New 1", "New 2"] });
```

### Pattern C: task edit check/uncheck/remove
```typescript
await core.updateTaskFromInput("task-1", { checkAcceptanceCriteria: [2] });
await core.updateTaskFromInput("task-1", { uncheckAcceptanceCriteria: [1] });
await core.updateTaskFromInput("task-1", { removeAcceptanceCriteria: [2] });
await core.updateTaskFromInput("task-1", { removeAcceptanceCriteria: [1, 2, 3] });
```

### Pattern D: Kombinierte Operationen
```typescript
await core.updateTaskFromInput("task-1", { checkAcceptanceCriteria: [1], removeAcceptanceCriteria: [2], addAcceptanceCriteria: ["New"] });
```

### Pattern E: Error-Handling (Core wirft Error statt exitCode)
```typescript
try {
  await core.updateTaskFromInput("task-1", { removeAcceptanceCriteria: [10] });
  expect(true).toBe(false);
} catch (error: unknown) {
  const msg = error instanceof Error ? error.message : String(error);
  expect(msg).toContain("Acceptance criterion #10 not found");
}
```
