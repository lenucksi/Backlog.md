## Problem
BacklogServer Tests binden an Port 0 (random), aber in --parallel können sich Event-Loops und Watcher überschneiden. Symptome: 404, 500, Timeout.

**Betroffene Files:**
- `src/test/server-assets.test.ts` — BacklogServer Port + asset serving
- `src/test/server-routes.test.ts` (oder ähnlich — die server endpoint tests)
- `src/test/modality-parity.test.ts` — Cross-Modality test (McpServer + BacklogServer + CLI)

## Fix 1: Server-Assets (src/test/server-assets.test.ts)

Das Problem ist vermutlich NICHT der Port (Port 0 = random), sondern dass Watcher/FileSystem-Instanzen kollidieren wenn zwei Server gleichzeitig laufen.

**Fix:** `afterEach` muss den Server sauber stoppen + `safeCleanup`:
```typescript
// Bereits vorhanden in Zeilen 67-73 — prüfen ob server.stop() wirklich awaited wird:
afterEach(async () => {
  if (server) {
    await server.stop();
    server = null;
  }
  await safeCleanup(TEST_DIR);
});
```
**Zusätzlich:** sicherstellen dass `beforeEach` den alten Server vor dem neuen stoppt:
```typescript
beforeEach(async () => {
  // Cleanup from previous test if something went wrong
  if (server) {
    await server.stop().catch(() => {});
    server = null;
  }
  TEST_DIR = createUniqueTestDir("server-assets");
  filesystem = new FileSystem(TEST_DIR);
  await filesystem.ensureBacklogStructure();
  await filesystem.saveConfig({ projectName: "Server Assets", statuses: ["To Do", "In Progress", "Done"], labels: [], milestones: [], remoteOperations: false });
  // ... rest
  server = new BacklogServer(TEST_DIR);
  await server.start(0, false);
  // ...
});
```

## Fix 2: Modality-Parity (src/test/modality-parity.test.ts)

**Problem:** Dieser Test hängt von McpServer (wird durch BACK-576.09 gefixt) UND BacklogServer (Port) ab. Nach den Fixes 576.09 + 576.13 sollte er durchlaufen.

**Zusätzlich:** In Zeile 47 wird `$` für git verwendet:
```typescript
await $`git init -b main`.cwd(testDir).quiet();
```
Das ist INFRA und OK.

**Mögliches Problem:** `const testDir = createUniqueTestDir("modality-parity");` auf describe-Ebene — in --parallel teilen sich alle Tests im File das selbe testDir. Das ist OK da Tests innerhalb eines Files serial laufen.
