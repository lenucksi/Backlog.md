## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
## Problem

`scripts/build.ts:18,25` runs guard build and Vite build sequentially:

```typescript
await $`bun run build:guard`;  // line 18 — takes ~17ms

const viteResult = Bun.spawnSync(["bun", "x", "vite", "build"]);  // line 25 — takes ~1s+
```

The guard build has zero dependency on Vite or vice versa. Running them sequentially wastes ~17ms of wall-clock time on every build. With parallel execution, both start together and total time = max(17ms, 1s+) instead of 17ms + 1s+.

## Location

- File: `scripts/build.ts`
- Lines: 18, 25-39

## Note

The guard build takes ~17ms in practice, so the actual wall-clock savings is marginal (~2-3%). However, this is a structural improvement that enables further parallelism (e.g., if guard build grows more checks later).

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. Wrap guard build in an async function: `const guardPromise = $`bun run build:guard`;`
2. Wrap vite build in an async function: `const vitePromise = viteBuild();`
3. Run both in parallel: `await Promise.all([guardPromise, vitePromise]);`
4. Keep same error handling — if either fails, the whole build fails
5. After both succeed, proceed to `bun build --compile` (unchanged)
6. Run `bun run build` and verify timing improvement
<!-- SECTION:PLAN:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
The actual savings depend on how long the guard build takes. On this project: ~17ms. So wall-clock savings is ~15ms. Not transformative now, but sets up the pattern for when more parallel work is added.

If using Vite JS API (593.3), the vite call becomes `build()`, which is already async — just `await Promise.all([guardBuild(), viteBuild()])`. If keeping spawnSync, wrap in a Promise.
<!-- SECTION:NOTES:END -->
