## Migration Patterns

### Task create:
```typescript
const core = new Core(TEST_DIR);
const { task } = await core.createTaskFromInput({ title: "Test" });
```

### Task edit (status, title, etc):
```typescript
await core.updateTaskFromInput("task-1", { status: "Done", title: "New Title" });
```

### Task view:
```typescript
const task = await core.filesystem.loadTask("task-1");
expect(task?.title).toBe("Test");
```

### Task list:
```typescript
const tasks = await core.filesystem.listTasks();
expect(tasks.length).toBeGreaterThan(0);
```

### Board:
```typescript
const core = new Core(TEST_DIR);
const tasks = await core.filesystem.listTasks();
// Board formatting is display logic — if test checks CLI output format, mark as CLI-CONTRACT
```

### INFRA (behalten):
- `git init` + `git config` → `// INFRA: git setup`

### CLI-CONTRACT (behalten als Subprocess):
- Help text tests (`--help`)
- Version tests (`--version`)
- Tests die CLI-spezifische Output-Formatierung prüfen (board coloring, plain output format)
- TTY behavior tests
- Interactive wizard tests
