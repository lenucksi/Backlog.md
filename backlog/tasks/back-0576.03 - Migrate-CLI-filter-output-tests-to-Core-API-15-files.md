## Migration Patterns

### Task create/list/edit/view → Core API
```typescript
const core = new Core(TEST_DIR);
await core.createTaskFromInput({ title: "Test", status: "todo" });
const tasks = await core.filesystem.listTasks();
await core.updateTaskFromInput("task-1", { status: "Done" });
const task = await core.filesystem.loadTask("task-1");
```

### Search:
Check `core` or `filesystem` for search method. If none exists, keep as CLI-CONTRACT.

### Config tests:
```typescript
const core = new Core(TEST_DIR);
const config = await core.filesystem.loadConfig();
expect(config?.projectName).toBe("...");
// For set operations: core.filesystem.updateConfig({ ... })
```

### CLI-CONTRACT (behalten als Subprocess):
- **cli-splash.test.ts**: splash/help/version output ist CLI-CONTRACT
- **cli-smoke.test.ts**: smoke tests testen CLI-Gesamtfunktion — evtl. CLI-CONTRACT
- **cli-plain-output.test.ts**: plain output formatting ist CLI-CONTRACT
- **cli-auto-plain-non-tty.test.ts**: TTY detection ist CLI-CONTRACT
- Andere Tests die CLI-spezifische Output-Formatierung prüfen
