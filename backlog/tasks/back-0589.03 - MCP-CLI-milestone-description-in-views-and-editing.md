## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
**Parent task:** BACK-0589 — Milestone descriptions across all modalities

**DEPENDENCY:** Requires BACK-0589.01 (Core + REST milestone description update) to be done first — needs `setMilestoneDescription()` on the filesystem.

**Goal:** Show milestone description in MCP `milestone_list` and CLI `milestone list` output, and allow setting/updating description via MCP and CLI tools.

**What exists:**
- MCP `milestone_list` returns text: `{m.id}: {m.title}` per milestone — no description
- MCP `milestone_rename` has no description parameter
- CLI `milestone list` shows `  {id}: {label} ({done}/{total} done)` — no description
- CLI `milestone list --json` outputs `{key, label, milestone, doneCount, total, progress}` — no description
- CLI board shows milestone labels as section headers — no description
- TUI board shows milestone labels in filter/headers — no description
- CLI `milestone create <name> -d <text>` already supports description on creation
- After BACK-0589.01: `setMilestoneDescription()` available on filesystem

**What to build:**

1. **MCP `milestone_list`** (`src/mcp/tools/milestones/handlers.ts`):
   - Line 323: include description inline when present and non-default, truncated to ~60 chars

2. **MCP `milestone_rename`** (`schemas.ts` + `handlers.ts`):
   - Add optional `description?: string` parameter
   - After rename, if description provided, call `setMilestoneDescription()`

3. **CLI `milestone list --json`** (`src/commands/milestone.ts`):
   - Add `description` field to JSON output

4. **CLI `milestone list` text** (`src/commands/milestone.ts`):
   - Add optional `--show-description` flag

5. **TUI board** (`src/ui/board.ts`):
   - Optional — accept N/A if unclear where to place it

**Files to modify:**
- `src/mcp/tools/milestones/schemas.ts`
- `src/mcp/tools/milestones/handlers.ts`
- `src/commands/milestone.ts`
- `src/ui/board.ts` (optional)

**Design notes:**
- MCP `milestone_list` keeps text-block format — just enrich existing line
- CLI `--json` gets description unconditionally
- MCP rename only calls `setMilestoneDescription()` if description param is explicitly provided
