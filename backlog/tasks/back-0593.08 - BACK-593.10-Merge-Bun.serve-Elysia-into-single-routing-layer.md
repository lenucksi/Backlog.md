## Problem

Zwei Routing-Layer:

**Layer 1: Bun.serve.fetch()** (src/server/index.ts:194-241)
```
if(upgrade → websocket) return 101
if(/ → index.html)
if(/favicon → favicon.png)
if(/web/ || /assets/ || *.js → resolveAsset())
return app.fetch(req)  // Fallback zu Elysia
```

**Layer 2: Elysia app.fetch()** (src/server/router.ts:99-791)
- 41 API-Routes
- /assets/* (project files, handleAssetRequest)
- SPA-Fallbacks

**Konsequenzen:**
1. enrichRequest()-Hack: Config-Handler muessen Request mutieren (router.ts:93-97, 587-654) weil params nicht nativ verfuegbar
2. Asset-Shadowing: /assets/* wird von Bun.serve VOR Elysia abgefangen
3. WS in Bun.serve statt Elysia ws()
4. Request-Lifecycle ueber 2 Router verteilt -> Debugging doppelt komplex

## Ziel

Alles in Elysia. Bun.serve wird zu `Bun.serve({ fetch: app.fetch })`.
Kein `enrichRequest()`, kein `if(pathname...)` in index.ts.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
## Schritt 1 — Asset-Serving in Elysia

Vor API-Routes in router.ts:
```typescript
.get("/", async () => { const f = await spaHandler(); return new Response(await f.text(), { headers: { "Content-Type": "text/html" } }) })
.get("/favicon*", () => new Response(Bun.file(favicon), { headers: { "Content-Type": "image/png" } }))
.get("/web/:path*", assetHandler)
```

`getContentType()` wird Helper in router.ts oder aus index.ts importiert.
`/assets/*` bleibt als Elysia-Route — leitet zuerst an resolveAsset() fuer build assets,
bei 404 weiter an handleAssetRequest() fuer project assets (system.ts).

## Schritt 2 — WebSocket in Elysia

```typescript
app.ws("/ws", {
    open: (ws) => ctx.sockets.add(ws.raw),
    message: (ws) => ws.send("pong"),
    close: (ws) => ctx.sockets.delete(ws.raw),
})
```

`buildElysiaApp()` bekommt `ctx` oder callback fuer socket-events.

## Schritt 3 — enrichRequest() killen

4 call-sites (router.ts:587, 604, 637, 654):
```typescript
// ALT:
return config.handleRenameLabel(enrichRequest(request, params));
// NEU: Handler bekommen params direkt via Elysia ctx.params
.put("/api/config/labels/:name", ({ request, params: { name } }) => {
    return config.handleRenameLabel({ ...request, params: { name } } as any);
})
```

Config-Handler-Signaturen ggf. auf (params, request) umbauen.

## Schritt 4 — start() aufraeumen

Von ~50 Zeilen fetch-Handler zu:
```typescript
this.server = Bun.serve({
    port: finalPort,
    fetch: app.fetch,
    websocket: { ... },  // oder via Elysia ws()
    error: this.handleError.bind(this),
});
```

applyNoStoreHeaders() wird `app.onAfterHandle()` Middleware.
