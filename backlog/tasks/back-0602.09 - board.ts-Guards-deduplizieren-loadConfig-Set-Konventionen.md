## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Tech-Debt-Vorbereitung für die board.ts-Pane-Extraktion (0602.01–.07). Analog zu 0600.02 bei task-viewer-with-search.ts.

board.ts hat dieselben 3 Duplikationsmuster wie task-viewer-with-search.ts vor 0600.02 — zum Teil schlimmer.

**1. Guards deduplizieren (30→1)**:
30× `if (popupOpen || filterPopupOpen || modalOpen [|| moveOp] [|| currentFocus === "filters"]) return;` in keybinding-Handlern (board.ts Zeilen 658–1706). Ein `canHandleBoardKey()` Helper prüft alle Varianten.

4 Varianten aktuell:
- `popupOpen || filterPopupOpen || modalOpen` (3×)
- `+ moveOp` (8×)
- `+ currentFocus === "filters"` (7×)
- `+ moveOp + currentFocus` (7×)
- plus verkürzte ohne `moveOp` (5×)
Ziel: `if (!canHandleBoardKey()) return;` — alle 30 auf eine Form.

**2. loadConfig-Duplikation auflösen**:
6 × `loadConfig()` in board.ts (davon 5× für autoCommit). Zwei Paare ~90% identisch:
- `handleContentAreaComplete` + `handleGlobalComplete` (~30 Zeilen Duplikat)
- `handleContentAreaArchive` + `handleGlobalArchive` (~30 Zeilen Duplikat)
Ziel: Generische `handleComplete()` / `handleArchive()` Helper.

**3. Set-Replacement → Mutation**:
6× `selectedTaskIds = new Set()` — in board.ts Zeilen 273, 384, 409, 524, 1387, 1389.
Ziel: `.clear()` + `.add()` statt Reassignment (erhält Closure-Referenzen, siehe AGENTS.md §TUI State Patterns).

**4. Widget destroy/rebuild**:
`clearColumns()` + `createColumnViews()` – ~75 Zeilen destroy+rebuild-Machinery.
Ziel: In `rebuildColumns()` konsolidieren, kein leaky destroy/create im Caller.

**Wichtig**: Keine Änderungen an task-viewer-with-search.ts oder anderen Modulen. Reiner board.ts-Fix.

## Schritt 1: Guard Helper

```typescript
function canHandleBoardKey(): boolean {
  return !popupOpen && !filterPopupOpen && !modalOpen && !moveOp && currentFocus !== "filters";
}
```
Ersetzt alle 30 Guards. Vereinfacht auch die verkürzten Varianten — moveOp und currentFocus Checks werden vereinheitlicht (bisher inkonsistent).

## Schritt 2: loadConfig Helfer

Identifiziere die 4 Handler (handleContentAreaComplete, handleGlobalComplete, handleContentAreaArchive, handleGlobalArchive) und extrahiere in 2 generische Funktionen:
```typescript
async function handleTaskComplete(taskId: string, core: Core): Promise<void> { ... }
async function handleTaskArchive(taskId: string, core: Core): Promise<void> { ... }
```
Jeder Handler ruft loadConfig() 1× statt 2-3×.

## Schritt 3: Set-Replacement

```typescript
// Statt:
selectedTaskIds = new Set();
// Neu (6×):
selectedTaskIds.clear();

// Statt:
selectedTaskIds = new Set(allIds);
// Neu:
selectedTaskIds.clear();
allIds.forEach(id => selectedTaskIds.add(id));
```

## Schritt 4: rebuildColumns konsolidieren

Stelle sicher dass clearColumns() nur von rebuildColumns() aufgerufen wird, nicht von Callern die dann manuell createColumnViews() rufen.
