## Problem

Two separate Tailwind CSS compilation paths exist with version drift risk:

### Path A: @tailwindcss/vite plugin (^4.3.1)
In `vite.config.ts:12`:
```typescript
tailwindcss(),
```

### Path B: @tailwindcss/cli (4.2.2)
In `package.json`:
```
"build:css": "bun ./node_modules/@tailwindcss/cli/dist/index.mjs -i src/web/styles/source.css -o src/web/styles/style.css --minify"
```

### The dead plugin problem

`index.html` links `./styles/style.css` — the **pre-compiled** Tailwind output from `build:css`. The `@tailwindcss/vite` plugin only processes files that `@import "tailwindcss"`. Since `style.css` is already fully compiled, the plugin does **nothing**. It is dead config.

### Version drift

`@tailwindcss/vite` is `^4.3.1`, `@tailwindcss/cli` is pinned at `4.2.2`. If someone runs `bun update` and the Vite plugin gets a new version, the two paths could produce different CSS, leading to inconsistent styling between dev (Vite) and production (CLI) builds.

## Resolution Options

**Option A (Vite-only — recommended):** Link `source.css` in `index.html`, let Vite plugin handle Tailwind during both dev and build, remove `build:css` script + `@tailwindcss/cli` dep.

**Option B (CLI-only):** Remove `@tailwindcss/vite` from config and deps. Keep `build:css` as explicit pre-build step, add it to the `build` pipeline.

## Location

- vite.config.ts line 12
- package.json line 31 + line 78
- src/web/index.html `<link>` tag
