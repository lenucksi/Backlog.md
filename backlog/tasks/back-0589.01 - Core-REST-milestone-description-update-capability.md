## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
**Parent task:** BACK-0589 — Milestone descriptions across all modalities

**DEPENDENCY:** This task is the foundation — subtasks BACK-0591 and BACK-0592 depend on this being done first.

**Goal:** Add ability to set/update milestone descriptions at the filesystem layer and expose it via REST API.

**What exists:**
- `Milestone.description` already in the type system (`src/types/index.ts:199`)
- `parseMilestone()` extracts `## Description` section from milestone files
- `createMilestone(title, description?)` sets initial description
- `renameMilestone()` has `rewriteDefaultMilestoneDescription()` that only touches auto-generated "Milestone: {title}" descriptions — custom descriptions are preserved
- REST `PUT /api/milestones/:id` only handles title rename, no description support
- `MilestoneBucket` type lacks `description` field

**What to build:**

1. **Filesystem** (`src/file-system/operations.ts`):
   - Add `setMilestoneDescription(identifier: string, description: string): Promise<...>` method:
     - Uses `findMilestoneFile()` to locate milestone
     - Replaces the `## Description` section body with the new text (use same regex pattern as `rewriteDefaultMilestoneDescription`)
     - If description is empty string, set to default `Milestone: {title}`
     - Returns `{ success, milestone }`
   - Add `description` field to `MilestoneBucket` in `src/types/index.ts`
   - Update `buildMilestoneBuckets()` in `src/web/utils/milestones.ts` to populate `description` from the milestone entity

2. **REST API** (`src/server/handlers/milestones.ts`):
   - Extend `handleUpdateMilestone()` to accept `description?: string` in request body
   - If `description` is provided (even empty string), call `setMilestoneDescription()`
   - Keep existing title rename logic working unchanged

3. **API Client** (`src/web/lib/api.ts`):
   - Extend `updateMilestone()` signature to accept optional `{ title, description? }` instead of just `title: string`
   - Pass `{ title, description }` in request body

4. **MCP schema** (`src/mcp/tools/milestones/schemas.ts`):
   - This is handled by subtask BACK-0592 but the schema for `milestone_rename` could get a `description` field added here if simpler

**Files to modify:**
- `src/types/index.ts`
- `src/file-system/operations.ts`
- `src/server/handlers/milestones.ts`
- `src/web/lib/api.ts`
- `src/web/utils/milestones.ts`

**Design notes:**
- Keep `renameMilestone()` + `rewriteDefaultMilestoneDescription()` as-is — only add the new setter
- Use the existing regex pattern from `rewriteDefaultMilestoneDescription` (line 1148) to find/replace the description section
- If `createMilestone` is called with no description, default to `Milestone: {title}` (current behavior, keep it)
