## Migration Patterns

Die meisten MCP-Tests haben nur `git init` + `git config` calls. Backlog CLI Subprocess Calls sind selten und meistens setup-only.

### Prüfe zuerst: wie viele BACKLOG CLI calls sind wirklich da?
```bash
grep -c 'bun.*src/cli\.ts\|bun.*CLI_PATH' src/test/mcp-*.test.ts
```

Die meisten sind vermutlich `git init` — die bleiben als INFRA.

### Falls backlog CLI calls existieren:
```typescript
const core = new Core(TEST_DIR);
await core.createTaskFromInput({ title: "Test", status: "todo" });
// oder für documents: core.createDocument({ title: "Doc", content: "..." })
```

### INFRA (behalten):
- `git init` + `git config` → `// INFRA: git setup`

### CLI-CONTRACT (behalten):
- MCP server process spawning tests (testen ob MCP-Server korrekt startet/stoppt)
- MCP stdio tests
